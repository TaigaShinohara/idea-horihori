# Google Workspace 連携セットアップ手順（v0.5.0）

完成した企画書（企画メモ）を、アプリから直接 Google ドキュメント化する
連携のための、Google Cloud コンソール側のセットアップ手順。

アプリ側の実装は完了済みで、**この手順で作ったクライアント ID を
ビルドに渡せば動く**状態になっている。逆に、この手順が済むまでは
アプリの設定画面で連携カードが「未設定（セットアップ待ち）」と表示され、
連携以外の機能は通常どおり使える。

所要時間の目安: 15〜20分（本人の操作は、画面の指示に沿った許可・作成が数回）。

## 前提（固定値）

| 項目 | 値 |
|---|---|
| パッケージ名（Android） | `com.taigashinohara.horihori` |
| 署名証明書 SHA-1 | `DC:95:B1:92:C3:73:D0:58:79:95:4E:FA:9C:0D:77:59:08:43:C3:C5` |
| 有効化する API | Google Drive API のみ |
| 要求スコープ | `https://www.googleapis.com/auth/drive.file` のみ |

- スコープは **drive.file**（このアプリが作ったファイルだけにアクセス可能）
  に絞ってある。ドライブ全体へのアクセス（フル Drive スコープ）は使わない。
- 上記 SHA-1 はプロジェクト専用キーストア（`.local/horihori.keystore`）の
  もの。全バージョン共通なので、登録は1回でよい。
  将来 Play ストアへ出す場合は、Play App Signing の署名 SHA-1 が別途
  必要になる（その時に同じ手順でクライアントを追加する）。

## 手順

### 1. Google Cloud プロジェクトを作る

1. https://console.cloud.google.com/ を開き、普段使う Google アカウントで
   サインインする。
2. 上部のプロジェクト選択 →「新しいプロジェクト」→ 名前は
   「アイデアホリホリ」など分かりやすいもので作成する。

### 2. Google Drive API を有効化する

1. 左メニュー「APIとサービス」→「ライブラリ」を開く。
2. 「Google Drive API」を検索して開き、「有効にする」を押す。

### 3. OAuth 同意画面を設定する

1. 「APIとサービス」→「OAuth 同意画面」を開く。
2. ユーザータイプは「外部」を選んで作成する。
3. アプリ名「アイデアホリホリ」、ユーザーサポートメールとデベロッパー
   連絡先は自分のメールアドレスを入れて保存する。
4. 「スコープ」画面では、何も追加しなくてよい（drive.file はアプリ実行時に
   要求する）。※ もし追加する場合は `.../auth/drive.file` のみ。
   **ドライブ全体のスコープ（`.../auth/drive` 等）は追加しないこと。**
5. 「テストユーザー」画面で、**アプリで使う自分の Google アカウントを
   テストユーザーとして追加する**。同意画面が「テスト」状態の間は、
   ここに登録したアカウントでだけサインインできる（自分用ならこれで十分）。
   公開ステータスを「本番環境」に進めるのは、ストア公開のタイミングでよい。

### 4. Android 用 OAuth クライアントを作る

1. 「APIとサービス」→「認証情報」→「認証情報を作成」→
   「OAuth クライアント ID」を開く。
2. アプリケーションの種類は「Android」を選ぶ。
3. パッケージ名に `com.taigashinohara.horihori` を入れる。
4. SHA-1 証明書フィンガープリントに
   `DC:95:B1:92:C3:73:D0:58:79:95:4E:FA:9C:0D:77:59:08:43:C3:C5` を入れる。
5. 「作成」を押す。**このクライアントの ID はアプリに渡す必要はない**
   （Android ではパッケージ名＋SHA-1 で自動照合される）。

### 5. Web 用 OAuth クライアントを作る（アプリに渡す ID）

1. もう一度「認証情報を作成」→「OAuth クライアント ID」を開く。
2. アプリケーションの種類は「ウェブ アプリケーション」を選ぶ。
3. 名前は任意（例: アイデアホリホリ Web）。リダイレクト URI 等は不要。
4. 「作成」を押すと **クライアント ID**（`....apps.googleusercontent.com`）
   が発行される。これを次の手順でビルドに渡す。
   （クライアント ID は秘密情報ではない。ただしシークレットの方は
   アプリでは使わないので、どこにも貼らないこと。）

### 6. クライアント ID をビルドに渡す

この VM のビルドでは、`.local/dart-defines.env`（git 管理外）に
KEY=VALUE で書くと `./build.sh` が自動で読み込む。

```
GOOGLE_WEB_CLIENT_ID=<手順5のクライアント ID>
```

通常の Flutter ビルド環境では、同等に
`--dart-define=GOOGLE_WEB_CLIENT_ID=...` を渡せばよい。

この ID が入ったビルドでは、設定画面の「Google Workspace」カードが
「Googleでサインイン」ボタンを表示するようになる。入っていないビルドでは
「未設定（セットアップ待ち）」表示のままになる（故障ではない）。

### 7. 動作確認

1. 上記ビルドのアプリを起動し、設定 →「Google Workspace」カードで
   「Googleでサインイン」を押す。手順3でテストユーザーに登録した
   アカウントでサインインし、ドライブへのアクセス（アプリが作った
   ファイルのみ）を許可する。
2. 企画メモのあるアイデアを開き、「Googleドキュメントで開く」を押す。
3. 完了ダイアログが出て、「開く」から Google ドキュメントとして
   開ければ成功。ドライブの「最近使用したアイテム」にも
   「（タイトル） 企画書 v（版数）」が現れる。

## 注意・既知の割り切り

- **iOS は未対応**: iOS 用クライアント ID の受け口（`GOOGLE_IOS_CLIENT_ID`）
  はコード側に用意してあるが、iOS の URL スキーム登録等の実機セットアップは
  未実施。現行の対象は Android のみ。
- 同じ企画メモを送るたびに**新しいドキュメントが作られる**（上書き更新は
  しない）。版ごとに残るのは企画メモの版管理と同じ考え方。
- サインインの実疎通は、実機＋本人アカウントでの確認待ち
  （この手順書の手順7がその確認になる）。
