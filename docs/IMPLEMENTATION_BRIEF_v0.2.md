# 実装指示書 — アイデアホリホリ v0.2.0

対象リポジトリ: https://github.com/TaigaShinohara/idea-horihori （このファイルの置き場所と同じ repo）
正本: `docs/DESIGN.md` §13（採用アイデア）／ `docs/ART_DIRECTION.md`（見た目）／ `docs/HANDOVER.md`（現在地）
現行: v0.1.2（versionCode 3、テスト44件合格）。本指示書の成果物は **v0.2.0 / versionCode 5**。

## 共通ルール（全項目に適用）

- 既存データの読み込みを壊さない。モデルへの追加項目はすべて任意（nullable / デフォルト値つき）とし、旧 JSON がそのまま読めること。単体テストで旧形式 JSON の復元を1件確認する。
- 純ロジック（プロンプト生成・整形・判定）は UI から分離してテスト可能に保つ（既存の `prompts.dart` / `fallback.dart` / `dig_mode.dart` の流儀に合わせる）。
- 見た目: Simple Glass のまま。新規の面は ART_DIRECTION の既定値から選ぶ。主ボタンのベタ色は `#B34E14` 固定（変更しない）。コントラスト 4.5:1 未満の文字色を作らない。
- 情報量: 既定では畳む／隠す。常時表示を増やすのはモードバッジの拡張のみ。
- 仕上げ: `flutter test` 全合格（既存44件＋追加分）、`flutter analyze` エラーなし、`./build.sh` でビルド、APK 名は `アイデアホリホリ_v0-2-0.apk`（ドットは1つだけ）、署名は `.local/horihori.keystore`（このマシン上でのみ存在。無い環境では新規に作らず、署名なしビルドで止めて報告する）。

## 項目1: 掘り方モード（友達／上司）

**目的**: 深掘りの質問の口調と観点を切り替える。名称は本人の決定どおり。

- モデル: `enum DigStyle { friend, boss }` を新設（`lib/dig_mode.dart` に追加が自然。既存の `DigModeKind` は AI／定型の表示用で別物なので混ぜない）。
- 永続化: 設定と同じ保存領域に `dig_style_v1`（`friend` / `boss`）を保存。既定は `friend`。
- UI:
  - 深掘り開始前（詳細画面の「深掘り」導線付近）と深掘り画面の両方で切り替えられる。深掘り画面では既存モードバッジの隣に現在のスタイルが分かる表示を足す（例: 「AIで深掘り中・友達モード」）。
  - 切り替えはセッション途中でも可。以後の質問から反映する。
- プロンプト（`Prompts.nextQuestion` / `summarize` に `DigStyle` 引数を追加）:
  - friend: 「友達として並走するインタビュアー。相手の発想を広げ、肯定しながら次の一歩を一緒に考える。否定から入らない。」
  - boss: 「上司として的確に指摘するレビュアー。甘い前提・曖昧な対象・根拠のない楽観を具体的に突く。ただし人格否定はせず、指摘には必ず改善の方向を添える。」
- 定型フォールバック（`FallbackQuestions`）: 質問の骨格は共通でよいが、boss のときだけ各質問の前置き／言い回しを詰める調子に変える差分を用意する（全問作り直しは不要。前置き1文の差し替え程度）。
- 受け入れ条件:
  - [ ] 再起動後もスタイルが保持される
  - [ ] 両スタイルでプロンプト文が変わることを単体テストで確認
  - [ ] 既存セッションの再開時にスタイル未保存でも落ちない

## 項目2: 視点掘り（お金／技術／使う人）

- モデル: `enum DigViewpoint { none, money, tech, user }`。セッション単位で保持する（`DigSession` に任意項目 `viewpoint` を追加。旧データは `none` 扱い）。
- UI: 深掘り画面の上部に視点チップ（通常／お金／技術／使う人）を置く。選択中だけアクセント色。通常は `none`。
- プロンプト: 視点が選ばれている場合、`nextQuestion` に1文追加する。
  - money: 「特にお金の視点（誰が・いくら・どう払うか／続けられるか）から掘る」
  - tech: 「特に技術の視点（作れるか・何が難しいか・既存技術で足りるか）から掘る」
  - user: 「特に使う人の視点（誰の・どんな場面の・何が嬉しいか）から掘る」
- 受け入れ条件:
  - [ ] 視点つきセッションを途中保存→再開しても視点が復元される
  - [ ] プロンプトへの反映を単体テストで確認

## 項目3: 逆張り質問（1セッションに1問だけ）

- 仕様: 5問セッションの **4問目** に「このアイデアが失敗するとしたら、何が原因だと思う？」系の質問を1問だけ混ぜる。2問以上は出さない。
- 実装:
  - `DigSession` に任意項目 `contrarianAsked`（bool、既定 false）を追加し、出したら true にして保存する。再開時に二重に出ないこと。
  - AI 経路: 次が4問目（answers が3件）かつ未出なら、`nextQuestion` に「今回は逆張りとして、失敗要因を聞く質問にする」指示を足す。
  - 定型経路: `FallbackQuestions` の4問目を逆張り固定文にする（選択肢は「需要がない／作りきれない／続けられない」＋広げる枠の流儀に合わせる）。
- 受け入れ条件:
  - [ ] AI／定型どちらの経路でも逆張りは1セッション1回だけ（単体テスト）
  - [ ] 3問で「いったんまとめる」した場合は逆張りが出なくてもよい（仕様として許容）

## 項目4: 企画の体力測定

- 仕様: 企画メモ完成時に「作りやすさ」「ワクワク度」を静かに添える。％や点数で追い詰めない表示にする（例: ●○○ の3段階＋短い言葉）。
- モデル: `PlanMemo` に任意項目 `ease` / `spark`（int 1〜3、nullable）を追加。旧メモは null＝表示なし。
- 生成:
  - AI 経路: `summarize` の出力 JSON に `"ease":1-3,"spark":1-3` を追加し、`parseMemo` で取り込む（範囲外・欠落は null）。
  - ローカル経路（`LocalMemoBuilder`）: 回答数と各項目の埋まり具合からの簡易ルールで決める（例: 項目が全部埋まれば ease 2 以上、など。単純で説明可能なルールにし、コメントに残す）。
- UI: 詳細画面の最新メモの末尾に小さく1行（例: 「作りやすさ ●●○ ／ ワクワク度 ●●●」）。旧メモ（折りたたみ側）には出さなくてよい。
- 受け入れ条件:
  - [ ] 旧データのメモ表示が変わらない（null で行自体が出ない）
  - [ ] AI／ローカル両経路で値が入ることを単体テストで確認

## 項目5: 開発指示書の書き出し

- 仕様: 育った企画メモを「アプリを作って」と他の AI／開発者に渡せる指示文に変換し、コピー／共有できる。
- 実装: 純関数 `buildDevBrief(Idea idea)` を新設（`lib/` に新規ファイル可）。構成:
  1. 見出し: 「アプリ開発の指示書: {タイトル}」
  2. 企画メモ最新版の5項目（What／誰に／なぜ／どうやって／次の一歩）
  3. 体力測定があれば1行
  4. Q&A の要点（全セッションの質問→回答を短く列挙）
  5. 締めの定型文: 「この企画でアプリを作ってください。まず設計案と画面一覧を出し、最小構成で動くところまで作ってください。」（過剰に盛らない）
- UI: 詳細画面に「指示書を書き出す」ボタン → プレビュー画面（またはダイアログ）→「コピー」と「共有」。共有は新規依存を増やさず、まずクリップボードコピーを必須、共有シートは既存依存の範囲で可能なら。
- 受け入れ条件:
  - [ ] 整形結果が単体テストで確認できる（見出し・5項目・Q&A が含まれる）
  - [ ] メモが無いアイデアではボタンが押せない（または非表示）

## 項目6: 名前決めアシスト

- 仕様: メモが1つ以上あるアイデアで、アプリ名の候補を3つ出す。表示のみ（名前を勝手に変えない）。
- 実装:
  - AI 経路: `Prompts.nameCandidates(title, memo)` を追加。出力は JSON の配列3件。短く・呼びやすく・日本語／英語の混在可、という条件をプロンプトに含める。
  - ローカル経路: タイトルと What の語を組み合わせる簡易候補（例: 語の連結、語尾の付け替え）で3件。品質は最低限でよい。
- UI: 詳細画面に「名前候補を出す」→ ボトムシートかダイアログで3件を並べるだけ。
- 受け入れ条件:
  - [ ] AI／ローカル両経路で必ず3件返る（単体テスト）
  - [ ] メモ無しでは実行できない

## 項目7: 回答履歴＋1問もどる

- 履歴表示:
  - 深掘り画面: 質問カードの下に「これまでの回答」を `ExpansionTile` 等で畳んで置く。既定は畳んだ状態。今セッション分を新しい順でなく時系列で Q→A 表示。
  - 詳細画面: 「深掘りの記録」として全セッション分を畳んで見返せる（セッションごとに小見出し＋開始日）。
- 1問もどる:
  - **前提の設計判断**: 現在の `QaEntry` は選択肢を持っていないため、そのままでは質問を完全復元できない。回答を保存するタイミングで `QaEntry` に任意項目 `choices`（List<String>、nullable）を追加して記録すること。旧データの回答は choices が無いので、「もどる」対象は choices を持つ最新の回答のみ可（無い場合はボタンを無効化）。
  - 動作: 現在セッションの最後の回答を取り消し、その質問（文＋選択肢）を `pendingQuestion` に復元して保存する。逆張りだった場合は項目3の `contrarianAsked` も false に戻す。
  - 回答が0件なら押せない。
- 受け入れ条件:
  - [ ] 取り消し→再回答→保存→再起動で状態が一致する（単体テスト: 純ロジック化した取り消し関数）
  - [ ] 旧データ（choices 無し）でボタンが無効化され、クラッシュしない

## 項目8: タイトル・メモの編集

- 仕様: 詳細画面でタイトルとメモ（note）を編集できる。
- 実装: 詳細画面に編集ボタン → ダイアログ（タイトル1行＋メモ複数行）→ 保存は `IdeaStore` 経由で永続化。空タイトルは保存不可（無効表示）。
- 受け入れ条件:
  - [ ] 編集が再起動後も保持される
  - [ ] アーカイブ済みアイデアでも詳細から編集できるかは現行の導線に従う（新規導線は作らない）
