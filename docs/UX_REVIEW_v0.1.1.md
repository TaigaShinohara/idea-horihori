## 総合判定

**要改善（土台は良い）。**

コンセプトの核（1行ストック → 1画面1質問 → 型でメモ化）は全画面で一貫し、情報量の抑制も設計どおりに守られている。一方で、**「AIで深掘りする」というコンセプトの中心が、利用者からは見えない**（どのモードで動いているか一切表示されず、失敗も無言で吸収される）、**深掘りの山場である「メモ完成」の瞬間に演出も遷移もない**、という体験の芯に関わる欠落が残る。見た目の問題ではなく、信頼と達成感の問題として必須修正に挙げる。

## 必須修正

### K1. AI／定型モードが利用者に一切開示されず、失敗も無言で消える
- 根拠: concept-driven-ux（コンセプト＝「ボタン一つでAIに深掘りさせる」が体験の核）／DESIGN §9「オフライン時は深掘りだけ『ネットが必要』と静かに表示」が未実装／状態の完全性（simple_glass quality §3、minimal 情報の後出し原則の逆転＝必要な状態情報が無い）
- 該当: `ai_backend.dart` の `ResilientBackend`（例外を全て握りつぶしてローカルへ切替）、`dig_screen.dart` 全体（モード表示なし）、`settings_screen.dart`（キー設定済みかどうか・AIが有効かの状態表示なし）
- 内容: キー未設定・キー不正・オフライン・API失敗の4状態がすべて「定型質問が出る」同じ見た目に潰れる。利用者は AI が働いたのか、壊れているのか、キーが効いているのかを永遠に判別できない。コンセプトの売りが検証不能なままになる。
- 解消条件: 深掘り画面に現在のモードが1行／バッジで常時分かること（例: 「AIで深掘り中」「定型モード（キー未設定）」）。API失敗時は少なくともセッションに1回、静かな通知で切替を知らせること。設定画面に現在の有効状態（AI有効／定型モード）が出ること。

### K2. 「まとめる」完了の山場がなく、遷移先によっては作ったメモを見られない
- 根拠: experience-balance（テンションカーブ：系列の山場＝メモ完成に強さが割り当てられていない）／ART_DIRECTION「動き：メモ生成→成長バーの伸び」が未実装（アニメーションコード自体がアプリ内に存在しない）
- 該当: `dig_screen.dart` の `_summarize()`（スピナーの後に無言で `Navigator.pop` するだけ）
- 内容: ホームのカードから深掘りを始めた場合、完了後はホームへ戻され、**完成した企画メモは表示されない**（詳細から始めた場合だけ詳細に戻って見える）。体験のクライマックスで成果物を見せないのは導線の欠落であり、種→実への成長の瞬間も祝われない・見えない。
- 解消条件: まとめ完了後は起動元によらず企画メモ（詳細）へ遷移して完成したメモを見せること。あわせて成長の変化が目で追えること（バーの伸びのアニメーション等、意味のある動き1つでよい）。

### K3. 初回体験に導線がなく、BYOK の設定へ到達できない
- 根拠: mobile_onboarding（最初の小さな成功への接続、価値が伝わる前に設定を求めない代わりに「必要な時点で案内する」）／minimal_information_design 原則5（後出し：必要になったタイミングで出す）
- 該当: `main.dart`（起動即ホーム、初回判定なし）、`home_screen.dart` 空状態、`settings_screen.dart`（キー取得先の案内なし。「自分のキーを入れると」とだけ書かれ、どこで取るかが無い）
- 内容: オンボーディング自体が無いことは、この道具型アプリでは許容できる（空状態＋FABで最初のストックは成立している）。問題は**AI 深掘りという核機能への導線が皆無**なこと。歯車アイコンの先にキー欄があると気づく手がかりが、どの画面にも、どのタイミングにも無い。K1 と合わせ、多くの利用者は定型質問だけを「このアプリの全部」だと思って終わる。
- 解消条件: フルオンボーディングは不要。初回の深掘り開始時、またはキー未設定で深掘りした時に1回だけ「キーを入れるとAIが質問するようになる」案内を設定画面への導線付きで出すこと。設定画面にキー取得先（AI Studio）の案内を1行足すこと。

### K4. 「答える」ボタンが無言で無反応になる状態がある
- 根拠: 状態の完全性（simple_glass quality §3：無効状態の見分けと理由）／minimal（判断の手がかりを消さない）
- 該当: `dig_screen.dart` の `_answer()`（未選択・未入力なら何も起きずに戻る。ボタンは常時有効な見た目）、`home_screen.dart` クイック追加の「ストックする」（タイトル空でも押せて無反応）、`dig_screen.dart` の「いったんまとめる」（初回0回答時のみ無効だが理由が分からない）
- 内容: 押せる顔をしたボタンが無言で死ぬのは、利用者に「壊れた？」と思わせる典型。特に深掘りは毎問触る主ボタンで、選択チップと自由入力のどちらが優先されるか（入力すると選択が外れる等）も見た目から読めない。
- 解消条件: 回答が無い間は「答える」を無効の見た目にする（または押下時に不足を1行で示す）。クイック追加も同型に揃える。「いったんまとめる」の無効条件は文言か表示で理由が推測できること。

### K5. 詳細画面で主役（企画メモ）が深掘りボタンに従属し、旧メモが無限に積み上がる
- 根拠: meaningful_app_design（画面の主役は1つ。DESIGN §5 で S4 の「一番見せるもの」は企画メモと定義済み）／minimal 原則4（Bランクは畳む）・原則5
- 該当: `detail_screen.dart`（タイトル→成長バー→全面幅のベタ色「深掘りする」ボタン→その下にメモ、の順序。メモ全版が同じ重さのフルカードで縦に積まれ、版が増えるほど最新メモ以外を読む負荷が増える）
- 内容: 画面の意味づけと視覚の重みが逆転している。最新のメモが主役、旧版は履歴（Bランク）として畳むべきもの。
- 解消条件: 最新メモを最初・最大の主役に置き、深掘りCTAはメモの後か控えめな強さに降格すること。旧版は折りたたみ（見出し＝「メモ vN」だけで中身が推測できる形）へ移すこと。

### K6. 成長段階が絵文字＋バーだけで伝わり、文字ラベルが死んでいる
- 根拠: minimal 原則3（色・形だけで状態を伝えない。読み上げ名を消さない）／アクセシビリティ初歩（色・アイコン単独依存の禁止）
- 該当: `models.dart` の `GrowthStageX.label`（「種／芽／実」が定義されているのに UI のどこからも参照されていない）、`widgets/glass.dart` の `GrowthBar`（Semantics なし）、各画面の段階表示（絵文字のみ）
- 内容: 🌱🌿🌳 の対応は初見では自明でなく、スクリーンリーダーではバーの値も段階も伝わらない。せっかく用意したラベルが未使用なのは設計と実装の断線。
- 解消条件: 段階ラベルを小さな文字で併記する（または最低限 Semantics ラベルで段階と成長度を読み上げ可能にすること）。

### K7. 主ボタンのコントラストが静的推定で 4.5:1 を割る
- 根拠: simple_glass 読みやすさ正本（本文・補助 4.5:1 が最終ゲート）
- 該当: `widgets/glass.dart` の `kAccent = #D96C2C` に白文字（FAB、「答える」「深掘りする」「ストックする」等のベタ面ボタン全般）。静的推定で白／#D96C2C は約 3.3:1。大きな太字として 3:1 は満たす見込みだが、通常サイズのボタンラベルの 4.5:1 には届かない。一方 `kAccentDeep = #B34E14` は約 5:1 で合格圏。
- 解消条件: 実測（または同等の計算）で主ボタンのラベルが 4.5:1 以上になること。手段はベタ面を kAccentDeep 寄りにする、ラベルを濃色にする等、ART の「アクセント1色」の範囲で選ぶこと。あわせてダーク時の入力面（K外・推奨 R5）も同じゲートで測ること。
- 注記: 数値はコード値からの静的推定。実画面での測定は未実施（仮判定）。

## 推奨改善

- R1. クイック追加の2欄目（メモ）が DESIGN §5 の「入力欄1つだけ」と食い違う。メモ欄を「メモを足す」の後出しに畳むか、DESIGN 側を実態に合わせて改訂するか、どちらかに統一する（現状は正本と実装の不一致として記録）。
- R2. 深掘り中の回答履歴が見られない／1問前に戻れない。誤タップした選択肢は確定し、セッション中ずっと自分の回答を振り返れない。質問カードの下に「これまでの回答」を畳んで置く、または最終問だけでも戻れる余地を検討。
- R3. 詳細にタイトル・メモの編集手段がない（DESIGN §5 の S4 操作に「編集」とあるが未実装）。タイプミスしたアイデアを直せず、アーカイブ→再登録しかない。正本との不一致として、実装するか DESIGN から外すか決める。
- R4. 旧メモの扱いに加え、詳細のメモ見出しラベル（12sp）は simple_glass の補助文字下限 12.5sp を割る。13sp 以上へ。
- R5. 入力面がテーマ非連動: `dig_screen.dart` / `settings_screen.dart` の入力 fill が両テーマ共通で「白50%」。ダーク時は明るい文字×白50%面でコントラストが崩れる恐れ。ART の入力ガラス（84%／20%）とも数値が違う。テーマ分岐と正本値への寄せを行う。
- R6. ガラス数値の正本とのズレ整理: GlassCard は blur 12（ART／スキルは読み物 24px）、ライト不透明度 55%（飾り 40% 指定だが文字が乗るカードに飾りを使う指定自体が simple_glass の「文字が乗る面は読み物」と矛盾）。ART_DIRECTION の「カード＝飾りガラス」の行を見直し、面の使い分けと数値を正本に揃える。あわせてスペキュラハイライト（ふちのグラデーション）未実装・面のやんわりグラデーション未実装も、質感を名乗るなら段階的に寄せる。
- R7. 背景の緑の光（#7FB069）が ART の「アクセント1色・土台は中立」と無関係に2色目の役割色を持ち込んでいる。光はブランド色（土色）の濃淡に統一するか、緑を「成長」の色として ART に明記してから使う。
- R8. ホーム空状態の文案内「右上の📦から戻せるよ」は、実際のボタンが Material のアーカイブアイコンで 📦 ではない。指す対象と文が一致していない（到達確認の失敗）。アイコン名か位置の言い方に直す。
- R9. 小さいタップ領域: 「いったんまとめる」「あとで続きを掘る」の TextButton は高さが 48dp 目安に届かない。深掘りの離脱導線なので、押し外しがそのまま「保存されずに閉じたかも」という不安になる。余白で領域を確保する。
- R10. 一覧の検索・並べ替えなしは件数が増えると走査負荷になる。v1 の割り切りとして妥当だが、件数の目安（例: 30件超）を超えたら検索を足す、という判断条件だけ DESIGN に残す。
- R11. DESIGN §5 の画面表にアーカイブ画面（6画面目）が未記載。正本ドリフトとして追記する。
- R12. 深掘りのローディング（質問生成・まとめ生成とも無言スピナー、Gemini は最大30秒）には文言もキャンセルもない。「質問を考えているよ」等の1行と、待ちが長い場合の逃げ道（戻る）を検討。戻る自体は AppBar で可能だが、処理中であることが伝わらない。

## 良い点（残すべきもの）

- 一覧カードが「タイトル＋成長アイコン＋成長バー＋深掘りボタン」までで止まっており、DESIGN の minimal 指定を実装が裏切っていない。FAB はベタ色・右下固定で親指ルールにも合う。
- 深掘りは 1画面1質問・選択肢3つ・5問で区切り・途中保存と再開（pendingQuestion の復元）まで揃い、認知負荷の設計が最も丁寧な画面。
- 企画メモの型（何を作る／誰に／なぜ／どうやって／次の一歩）が固定で、版として積み上書きしない。見返す画面の情報設計として正しい。
- 主ボタン（CTA）をガラス化せずベタ色で維持している（simple_glass の禁止事項を回避）。アクセントも原則1色で運用されている。
- オフライン／キーなしでも定型質問で深掘りが完結するフォールバックは、機能としての状態の完全性を支えている（問題は K1 のとおり「見えない」ことだけで、仕組み自体は良い）。
- 設定のキーは伏字表示・端末内保存で、説明文にもその旨がある。BYOK の安全側の作りは妥当。
- アーカイブの安全設計（確認→取り消し可能→復元画面→削除はアーカイブ内でのみ確認付き）は v0.1.1 で水準に達した。

## バランス所見（experience-balance）

- 画面系列のテンション: 一覧（静）→ 深掘り（動・本編）→ 完了（**無音で終了**）→ 詳細（静）。山場であるはずのメモ完成にだけ強さが割り当てられておらず、系列全体が平坦。K2 はこの一点の解消である。
- 要素間の重み: 詳細の CTA＞メモ（K5）、設定の説明文＞入力欄そのもの、深掘り下部の3アクション（答える／まとめる／あとで）が同格に並び主従が弱い（「答える」だけベタ色で辛うじて区別）。
- 反復の疲労: 深掘りは毎問「チップか自由入力か」の判断を繰り返す構造。どちらか選ぶと他方が消える挙動は一貫しているが、初回に伝える手段がない（K3 の初回案内に含めて解消できる）。

## v0.1.2 での実装順の提案

1. **K1 モード開示**（深掘りにモード表示＋失敗時の静かな通知、設定に状態表示）— コンセプトの信頼の芯。実装も小さい。
2. **K2 完了導線**（まとめ後は詳細へ遷移しメモを見せる＋バーの伸び1つ）— 山場の回復。K1 と同じセッション体験の改修としてまとめて行うと効率が良い。
3. **K4 ボタンの状態**（答える／ストックするの無効表現）— 小さく確実に摩擦が減る。
4. **K3 初回案内**（初回深掘り時の1回だけのキー案内＋設定に取得先1行）— K1 の表示基盤の上に乗る。
5. **K5 詳細の主従**（最新メモ主役化、旧版は折りたたみ、CTA降格）— 画面改修として単独で。
6. **K6 段階ラベル**（併記または Semantics）— 小さいが全画面に触るので最後に一括。
7. **K7 コントラスト**（実測→ベタ面の色調整）＋ ついでに R4・R5 の文字サイズと入力面を同じ「読みやすさ」枠で直す。

推奨（R1〜R12）は、K5 と同時に R3・R11（DESIGN 正本との不一致解消）、K7 と同時に R6（ガラス数値の正本寄せ）を束ねると、正本と実装のドリフトをまとめて止められる。
